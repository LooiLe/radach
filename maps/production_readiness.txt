Production Readiness Checklist: APIs & External Services
=========================================================

To launch this application to a public audience, you must replace the public testing APIs with production-grade commercial APIs. 

### 1. Mapping, Routing, and Geocoding (Stadia & Nominatim vs Mapbox)

**Current Status (MVP Phase):**
*   **Map Tiles & Snap-to-Path Routing:** We use **Stadia Maps** (which incorporates Valhalla for trail routing). 
    *   *Why Stadia now:* It has a free tier of 2,500 requests/day that **does not require a credit card** to activate, making it perfect for prototyping and dev.
*   **Address & Location Search:** We use **Nominatim (OpenStreetMap Search)**.
    *   *Why Nominatim now:* It is completely free and has no daily cap, preserving our 2,500 requests/day Stadia quota for maps and trail-snapping routes.

**Production Recommendation (Scale Phase):**
When the app goes into full production, you should transition all mapping and geocoding services to **Mapbox**.
*   **Is Mapbox actually better?** Yes. Mapbox is the industry standard. Their routing engine is much faster and more accurate for trails, and their global geocoding (search) data is robust and fast.
*   **The Math:** Mapbox's free tier is massive. You get 50,000 map loads, 100,000 routing requests, and 100,000 search requests **every single month for free**.
*   **The Catch:** Mapbox requires a credit card on file just to activate the free tier (to prevent spam accounts), which is why we are using Stadia/Nominatim for the MVP.
*   **Why Nominatim must be replaced:** Nominatim's public server has a strict **1 request per second rate limit** and forbids high-volume or commercial usage. Under active production load, it will throttle or block your users' searches.

**How to migrate to Mapbox later:**
1. Create a Mapbox account and link a card to unlock the free tier.
2. Get your default public token.
3. Update `.env` to use `VITE_MAPBOX_API_KEY`.
4. Swap the Stadia and Nominatim endpoint URLs in `SubmitTrailPathPage.jsx`, `DirectionsPage.jsx`, `SpotsPage.jsx`, `AddSpotPage.jsx`, and map components to use Mapbox equivalents (Mapbox Tiles, Mapbox Directions, and Mapbox Geocoding).

### 2. Cloud Image Storage (Cloudinary)

**Current Status (MVP Phase):** 
Photos uploaded for Spots, Events, or Trail Paths are saved directly to the server's local hard drive (`/uploads`).

**Production Recommendation (Critical):**
If you deploy this app to a modern cloud host (like Heroku, Vercel, or Docker containers), the local hard drive is temporary. Every time the server restarts, **all uploaded images will be permanently deleted**.

You must switch to an external storage provider before launch:
*   **The Best Option:** **Cloudinary**. It has a generous free tier (25 monthly credits = ~25GB bandwidth).
*   **Why it's better than standard blob storage:** Cloudinary is an "Image CDN". It automatically resizes, compresses, and converts huge iPhone photos into tiny, fast-loading web images. This prevents massive image files from eating up mobile users' data plans when they browse trails out in the wild.

### 3. Production Security Checklist

Before going live, you must secure your active API keys (whether Stadia or Mapbox):
1. **Domain Restriction:** Log into your provider's dashboard and restrict the API key so it can *only* be used by your exact domain (e.g., `https://radachmaps.com`). This prevents people from stealing your key from the public frontend code and running up a bill.
2. **Environment Variables:** Never commit API keys to GitHub. Put them in your `.env` (frontend) and `application-prod.properties` (backend).
